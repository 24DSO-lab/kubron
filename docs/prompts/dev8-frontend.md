## Задачи (Фаза 1–2)

### 1. Цепочка зависимостей (ADR-0031 §8, этап 1)

- `ChainView.vue`: компактный путь `Report.chains` от затронутого ресурса до кандидата: вершины с состоянием, **`Missing` и `Unknown` помечены явно и разными** («нет» ≠ «не знаем»; для `Unknown` — причина), кандидат первопричины выделен как **«кандидат»**, не «причина». Доступность: цвет не единственный носитель смысла, есть текстовые метки, клавиатура, ARIA.
- Отчёт без `graph`/`chains` (старый инцидент) открывается как раньше, без пустого блока и без ошибок.
- `FindingsPanel.vue`: гипотезы с `explains` группируются (без потери данных); кандидат помечен. **Интерактивная карта зависимостей — вторая итерация, не делается.**

### 2. Метрики (ADR-0032 §6–§7)

- `MetricFacts.vue`/`EvidencePanel.vue`: факты `metric.*` со значением, единицей, окном и агрегатом (`value`, `unit`, `window`, `agg`, `limit`); форматирование чисел через `i18n/format.ts`.
- `MonitoringHint.vue`: блок «С включённым мониторингом диагноз будет точнее и полнее» по `MissingContext` `metrics.*`: при `not_installed` — ссылка на установку встроенного стека (существующий экран мониторинга); при `forbidden` — пояснение для администратора про роль `prometheus-proxy-access`; остальные причины — нейтральное пояснение. Блок появляется **только** при наличии такого `MissingContext`; без него — ничего не показывать. Тон спокойный, без рекламы.

### 3. Корреляция и проблемы (ADR-0033 §5–§7)

- `CorrelationBlock.vue` в расследовании: «Возможный общий источник» — источник, уверенность, начало, **число и список** затронутых нагрузок (`Total`, признак усечения), подтверждающие факты, **область потенциального влияния отдельно** от уже затронутых, ссылка на проблему. `low` — явно как подсказка. На `Unknown/forbidden` — пометка «список неполный: нет прав». Текст — «возможный», «вероятный», не «причина».
- `ProblemList.vue`, `ProblemView.vue`: список открытых проблем (источник, число участников, затронуто); экран проблемы — участники (ссылки на расследования), агрегированное затронутое множество, ручные действия: присоединить, отсоединить, объединить, создать из выбранных. Действия неприятных последствий — с подтверждением и пояснением, что **расследования не удаляются и не сливаются**. Кнопки действий скрыты/неактивны без права `operate` (повтори то, как сейчас определяются права в UI). Обновление по событию `problem.changed` (событие несёт только ID — подробности загружаешь RPC).

### 4. Отметка результата и статистика (ADR-0034 §2, §7)

- `OutcomeForm.vue`: обязателен только результат; остальное необязательно: подтверждённая гипотеза (как сейчас), отвергнутые гипотезы, для каждой рекомендации три состояния (**не отмечено / помогло / не помогло**, по умолчанию «не отмечено»), «помогло другое действие», «когда устранено» (только для `resolved`, ограничения по датам как в ADR), оценка кандидата корреляции (подтверждён / отвергнут / неизвестно), комментарий. Форма простая и не пугает полей: без отметок исход сохраняется.
- Пометки статистики в `FindingsPanel.vue` (данные — RPC `IncidentRuleStats`, ключ `(ruleId, ruleEpoch, code)`): «подтверждалась в N из M оценённых случаев в этом кластере»; у рекомендации — «помогала в N из M» или «ранее не помогала» (`previouslyUnhelpful`), типичное время устранения, повторение. **Только при `trusted`; иначе — число случаев без процента.** Ранжирование: гипотезы по-прежнему по уровню уверенности правила, внутри уровня — по точности; рекомендации **никогда не скрываются**. Уровень уверенности в интерфейсе не меняется.
- Повторение: баннер «было устранено …, подтверждённая причина …, помогало …» со ссылкой на предыдущее расследование (`recurrenceOf`).
- `RuleStatsPanel.vue`: таблица статистики кластера, размер выборки и неоценённые случаи рядом с цифрами, пояснение ограничений (только доведённые до отметки расследования; последние 200; в пределах retention), кнопка «Выгрузить статистику правил» (только с нужным правом; перед скачиванием — явное описание, что в файле есть и чего нет; никакой автоматической отправки).

### 5. Локализация и тесты

- Все строки интерфейса — в `incidents.json` en/ru/cn; паритет ключей между языками — тестом. Ключи причин `Missing`/`Unknown` вершин графа и причин метрик — у владельцев кодов (D3, D1); ты проверяешь, что в интерфейсе нет «сырых» кодов (неизвестный код → безопасный текст по умолчанию).
- Новые `vitest`-тесты рядом с `incidents.ui.test.ts`: рендер каждой фикстуры; **старый инцидент открывается без ошибок**; подсказка мониторинга только при соответствующем `MissingContext`; `Missing` и `Unknown` выглядят по-разному; проценты не показываются при выборке < 5; действия проблемы скрыты без `operate`; форма отметки собирает правильный `OutcomeInput` (включая «не отмечено» как отсутствие поля).
- `npm test` и `npm run build` без ошибок и предупреждений типов.
