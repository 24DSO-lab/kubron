# Общие правила для всех разработчиков

Этот файл читают все D1–D8 до начала работы. Он дополняет ADR-0031…0034 (`docs/adr/`) и `contracts.md`.

## Что прочитать

1. `docs/adr/0031-dependency-graph.md`, `0032-metrics-evidence.md`, `0033-correlation-problems.md`, `0034-feedback-loop.md` — целиком; затем `0024-kubron-intelligence.md` и `0026-shared-platform-foundation.md` как базу.
2. `docs/prompts/README.md` (матрица владения файлами, фазы) и `docs/prompts/contracts.md`.
3. Свой промпт `dev<N>-*.md`.

Ветка `refactor` — самая полная; работай от неё. ADR имеют статус «предложено»: реализуй как написано, а расхождение между ADR и кодом оформи вопросом тимлиду (комментарий в PR), не молчаливым отступлением.

## Окружение

Go 1.27.3 и vendor лежат в репозитории, в каталоге `.test`:

```bash
mkdir -p ~/go-1.27.3 && tar -C ~/go-1.27.3 -xzf .test/go1.27.3.linux-amd64.tar.gz
export PATH=~/go-1.27.3/go/bin:$PATH      # если архив распаковался иначе — поправь путь
tar -xzf .test/vendor.tar.gz               # создаёт vendor/ в корне репозитория
export GOFLAGS="-mod=vendor -tags=webkit2_41"
```

Файл `.test/build vendor` содержит команду, которой собирался vendor: `GOFLAGS=-tags=webkit2_41 go mod vendor`. Если vendor не совпадает с `go.mod`, запусти её, но **не коммить** `vendor/` и не меняй `go.mod`/`go.sum` без необходимости; новую зависимость добавляй только с обоснованием в PR (по умолчанию — нельзя).

Проверки перед каждым PR:

```bash
go build ./...
go vet ./...
go test ./internal/<свои пакеты>/... ./internal/app/... ./internal/k8s/...
golangci-lint run ./internal/<свои пакеты>/...   # конфигурация — .golangci.yml
```

Для фронтенда: `cd frontend && npm ci && npm test && npm run build` (скрипты уточни в `package.json`).

## Правила кода

- Каждый новый Go-файл начинается с заголовка, как в проекте:
  ```go
  // Copyright 2026 The Kubron Authors
  // SPDX-License-Identifier: Apache-2.0
  ```
- Комментарии к типам и функциям — на русском, коротко и по делу (как в существующем коде). Идентификаторы — английские.
- Доступ к кластеру из доменных пакетов — **только** через узкие интерфейсы `Reader`/`Provider`, объявленные в самом пакете. Пакеты `depgraph`, `signals`, `correlation`, `feedback` и `diagnose` не импортируют `internal/k8s`, `rest`, `clientcmd`, не создают клиентов и не читают Secret (их проверяет статический тест `internal/k8s/opsplatform_static_test.go`).
- **Секреты и значения.** Значения полей объектов, содержимое ConfigMap, тексты логов, имена ресурсов и namespace не пишутся в журнал, аудит, метрики Kubron и выгрузки. В отчёт и хранилище идут коды, идентификаторы ресурсов, параметры и числа (ADR-0022).
- **Детерминизм.** Диагностика — чистая функция от входных данных. Сортируй всё, что идёт в отчёт (узлы, рёбра, факты, гипотезы). Время берёт `Context.ObservedAt`/параметр, а не `time.Now()` внутри правил.
- **Ошибки частичные, а не фатальные.** Недоступность необязательного источника (метрики, граф, корреляция) даёт `MissingContext`/`Partial`, а не ошибку расследования. «Нет данных» не равно «значение 0»; `Missing` — только при `NotFound`, остальное — `Unknown` с причиной.
- **Обратная совместимость.** Все новые поля JSON — `omitempty`; сохранённые документы старых версий читаются без ошибок. Для каждого изменённого документа — тест чтения старого JSON.
- **Лимиты в коде**, не в настройках; значения — из ADR; изменение — только новым ADR.
- Локализация кодов — по ADR-0014 (en, ru, cn). Новый код без перевода в трёх языках не принимается.
- Тесты — табличные, на фикстурах; без обращения к реальному кластеру и сети. Фикстуры — в `testdata/`.

## Коммиты

Формат: `тип(область): краткое описание` (например, `feat(depgraph): построение графа от Pod`), далее пустая строка, пояснение и **ровно** такая подпись последней строкой:

```
Signed-off-by: Vadim <vmilyash@mts.ru>
```

Не добавляй `Co-Authored-By:` и `Claude-Session:`. Коммиты небольшие и осмысленные; сообщение — на русском.

## Работа с контрактами и чужими файлами

- Источник истины — `docs/prompts/contracts.md`. Реализуй сигнатуры буквально; если они мешают, предложи правку владельцу, не меняй у себя.
- Чужой файл не правится. Нужна правка — комментарий в PR владельца или issue. Исключение — файлы-заглушки, помеченные в `contracts.md` как «передаётся владельцу после Фазы 0»: после слияния скелета они принадлежат тому, кто назван.
- Пока зависимость не слилась, используй собственный фейк в тестах своего пакета и пиши код против `contracts.md`.

## Описание PR

Каждый PR содержит: что сделано (ADR и раздел), какие файлы затронуты (только свои), как проверить, что не вошло, **строку для CHANGELOG** (одно предложение, её соберёт D7) и список вопросов к тимлиду. Скелет-PR помечается `[skeleton]`.

## Definition of Done (для любой задачи)

- Все сценарии из твоего промпта покрыты тестами; `go build/vet/test` и линтер без замечаний.
- Нет изменений в чужих файлах; нет новых зависимостей.
- Старые данные читаются; результат детерминирован.
- Лимиты и пороги — константами с комментарием «ADR-00XX §N».
- Нет логирования значений; нет чтения Secret.
- Локализация (если вводились коды) в en/ru/cn.
