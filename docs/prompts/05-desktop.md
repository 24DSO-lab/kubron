# Промпт 5. SSO в десктопе (Wails)

Сначала прочитай `docs/prompts/README.md`, ADR-0018 (виды вызова `browser-loopback`, RFC 8252). Промпты 1–4 выполнены.
Этот шаг можно делать отдельным изменением: веб-версия от него не зависит.

## Задача

Вход в десктопное приложение через системный браузер и временный loopback-порт.

- Настройки: десктоп не читает переменные окружения сервера. Хранить параметры IdP (issuer, client id, claims, роль по
  умолчанию) в настройках приложения (рядом с остальными настройками, секретов нет: публичный клиент, только PKCE).
  Секрет клиента в десктопе не поддерживается.
- Метод `App.LoginSSO()` (Wails/RPC) — новый экспортируемый метод без `authz` (как `Login`): добавить в allowlist
  `internal/auth/policy_test.go` и `allowlist_matrix_test.go` с обоснованием. Метод:
  1. поднимает слушатель на `127.0.0.1:0`, строит redirect `http://127.0.0.1:<порт>/callback`;
  2. `sso.Begin`, открывает системный браузер (через `Platform`, а не напрямую — ядро не импортирует Wails);
  3. ждёт callback с таймаутом 5 минут и возможностью отмены (`context`), принимает один запрос на `/callback`,
     отвечает короткой HTML-страницей «Вход завершён, вернитесь в Kubron», закрывает слушатель;
  4. `sso.Complete`, затем `auth.LoginExternal` (локальный `users.json`; пользователи не общие между машинами).
  Обращения к IdP — `idpnet` с `Desktop: true` (http и loopback разрешены).
- Слушатель принимает только `127.0.0.1`/`::1`, проверяет `state`, не отдаёт ничего, кроме страницы результата;
  повторный и посторонний запрос отклоняются.
- Интерфейс: на экране входа десктопа кнопка SSO (тот же компонент, источник состояния — `AuthStatus`, поле `sso`
  заполняет ядро десктопа из настроек), экран настроек SSO для администратора с подсказкой, какой redirect URI
  зарегистрировать в IdP (`http://127.0.0.1:<порт>/callback`; в Authentik — регулярное выражение), ключи локали во всех языках.
- Важно: в десктопе нет «первого входа через SSO» — до создания администратора действует то же правило: SSO отклоняется.
- Тесты: поддельный IdP; успешный вход; отмена; таймаут; чужой `state`; два параллельных `LoginSSO` (второй отклоняется
  или отменяет первый — выбрать и зафиксировать в ADR-0059 дополнением к «Последствиям» новым ADR не нужно, достаточно
  раздела в ADR-0059, пока тот в статусе «предложено»).

## Критерии готовности

Проверки из README зелёные, включая `wails doctor`-совместимость сборки (`go vet ./...` в корне с заглушкой
`frontend/dist`); коммит `feat(desktop): OIDC sign-in via loopback` с `Signed-off-by` запушен в `refactor`.
