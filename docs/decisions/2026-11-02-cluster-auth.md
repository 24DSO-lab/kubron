## D-01. Библиотека системного хранилища ключей: `zalando/go-keyring`

- **Проблема.** Десктопу нужно хранить мастер-ключ шифрования учётных данных в Keychain, Credential Manager или Secret Service.
- **Варианты.** (а) `github.com/zalando/go-keyring`; (б) `github.com/99designs/keyring`; (в) вызывать системные утилиты самостоятельно.
- **Решение.** (а). Чистый Go, без cgo: проще кросс-сборка Wails (Windows, Linux, macOS) и меньше зависимостей в образе. Проект поддерживается:
  последний коммит в репозитории — 2026-07-24 (проверено клонированием 2026-11-02). У (б) последний коммит — 2022-12-19 (проверено так же).
  Мы храним только 32-байтный мастер-ключ, поэтому ограничения на размер секрета у хранилищ ОС не мешают. Файловый запасной
  вариант нужен нам собственный (`0600`, с видимым предупреждением), а встроенные файловые бэкенды (б) просят пароль и для
  неинтерактивной работы не подходят.
- **Последствия.** На Linux нужен запущенный Secret Service (D-Bus). На безголовых системах его нет: тогда мастер-ключ в файле `0600`,
  а интерфейс показывает, что ключ не защищён хранилищем ОС. Тикет A.6 проверяет доступность хранилища при старте.
- **Отмена.** Заменить пакет за интерфейсом `MasterKeyStore` (A.6); формат хранимых данных не меняется.

## D-02. Веб без PostgreSQL: ключ шифрования создаётся автоматически

- **Проблема.** `oidc-password` и новые личные данные не должны требовать PostgreSQL. Но без `KUBRON_SECRET_KEY` ключа нет.
- **Варианты.** (а) требовать `KUBRON_SECRET_KEY` всегда; (б) если не задан, создать случайный ключ один раз в каталоге данных (`0600`);
  (в) хранить без шифрования.
- **Решение.** (б) только для сервера без PostgreSQL (личный режим); с PostgreSQL `KUBRON_SECRET_KEY` остаётся обязательным (как в 3.1c).
  (в) недопустимо (ADR-0008). Создание ключа пишется в журнал; в документации предупреждение: ключ лежит рядом с данными, поэтому защищает
  от случайной утечки файла данных (бэкап, вложение в тикет), но не от человека с доступом к каталогу; для общего сервера нужен
  `KUBRON_SECRET_KEY` из Secret.
- **Последствия.** Потеря файла ключа означает потерю сохранённых данных входа (пользователь входит заново); бэкап ключа описан в `docs/backup.md` (A.6).
- **Отмена.** Сделать (а): сервер без ключа отказывается хранить учётные данные.
