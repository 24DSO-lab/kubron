# Решения: нативный провайдер GKE (тикет B.7b, ADR-0018, вторая волна)

Статус: **ждёт ревью человеком**.

Область: `internal/credential/providers/gke/`, регистрация в `BuildBroker`, многострочное секретное поле в диалоге входа.

## 1. Ключ сервисного аккаунта сохраняется (зашифрованно)

**Проблема.** Ключ сервисного аккаунта (JSON с закрытым ключом) не истекает сам. Токен живёт около часа, поэтому
без сохранения ключа пользователь вставлял бы файл заново каждый час.

**Варианты.**
1. Не сохранять: `Result.Save` остаётся `nil`, вызов повторяется после истечения токена (около часа).
2. Сохранять ключ, как refresh-токен других провайдеров (шифрует Broker, envelope, ADR-0008).

**Решение.** Вариант 2. Провайдер возвращает `Save` с нормализованным JSON: только `type`, `client_email`,
`private_key_id`, `private_key`. `token_uri`, `project_id`, `auth_uri` и прочие поля не сохраняются. Провайдер сам
ничего не шифрует и не пишет: данные получает Broker, который шифрует их до записи в хранилище. Область (`user` или
`team`) выбирает Broker; по ADR-0018 для интерактивных видов это `user`, и провайдер от неё не зависит.

**Последствия.**
- Утечка базы вместе с мастер-ключом раскрывает долгоживущий секрет, в отличие от refresh-токена, который можно
  отозвать у IdP. Для сервисного аккаунта нет эквивалента RFC 7009: «отключиться от кластера» удаляет запись у нас, но
  ключ остаётся действующим у Google, пока его не удалят в Google Cloud. В руководстве администратора (C.5) нужно
  написать: выдавать аккаунту минимальные роли, ротировать ключи, удалять ключ в Google Cloud при отзыве.
- Если сохраненный ключ больше не принимается (`invalid_grant`), запись стирается (`Save: []byte{}`), пользователю
  показывается новый вызов. Если Google недоступен, запись остаётся.

**Отмена.** Убрать строку `Save: k.normalized()` в `Continue`: провайдер перестанет сохранять, остальное не меняется.

## 2. Пакет `golang.org/x/oauth2/jwt` вместо `google.JWTConfigFromJSON`

**Проблема.** Промпт предписывал `google.JWTConfigFromJSON`. По исходникам x/oauth2 v0.37.0 эта функция берёт
`TokenURL` и `Audience` из файла ключа (`token_uri`), а пакет `google` содержит цепочку Application Default Credentials
и клиент metadata-сервера.

**Варианты.**
1. `google.JWTConfigFromJSON`, затем принудительно перезаписать `TokenURL` и `Audience`.
2. Свой разбор JSON и `jwt.Config` напрямую.

**Решение.** Вариант 2. Разбор JSON нужен в любом случае (лимит 16 КиБ, проверка `type`, `client_email` и PEM до
запроса, нормализация для `Save`). Пакет `google` не попадает в сборку вообще: тест `go list -deps` проверяет, что его
нет, а тест исходников разрешает только перечисленные импорты (нет `os`, `net`, `log`, SDK облаков). `TokenURL`
это константа `https://oauth2.googleapis.com/token`, `Audience` не задаётся и равен `TokenURL`.

**Последствия.** Новых модулей нет: нужен только `golang.org/x/oauth2 v0.37.0`, который уже есть в `go.sum` как
косвенная зависимость и после `go mod tidy` становится прямой. Не поддержаны «вселенные» с другим доменом
(`universe_domain`, не `googleapis.com`): ключ для них не получит токен.

**Отмена.** Перейти на `google.JWTConfigFromJSON` можно, но тогда тест `TestDependenciesDoNotLinkTheGoogleSearchChain`
придётся ослабить, а `TokenURL` и `Audience` перезаписывать вручную.

## 3. Отмена вызова доходит до сетевого запроса (адаптер к `Env.HTTP`)

**Проблема.** `jwt.Config` в x/oauth2 v0.37.0 отправляет запрос через `Client.PostForm` без контекста. Тест
`TestCancellationAbortsTheRequestInFlight` показал: отмена контекста запрос не прерывает, его ограничивает только таймаут
клиента (в `idpnet` 15 секунд). Подписанное утверждение ушло бы к Google уже после отмены.

**Варианты.**
1. Игнорировать (таймаут ограничит).
2. Запускать обмен в горутине и ждать контекст: запрос продолжается в фоне.
3. Передать библиотеке клиент, который привязывает каждый запрос к контексту и целиком делегирует `Env.HTTP.Do`.

**Решение.** Вариант 3 (`boundClient` в `token.go`). Это не свой транспорт в смысле правила 1: соединение, политика
SSRF, проверка редиректов, таймаут и лимит ответа остаются за `Env.HTTP`. Редиректы следует `Env.HTTP`, внешний клиент
сам их не выполняет (`ErrUseLastResponse`), поэтому политика проверяет каждый переход ровно один раз.

**Последствия.** `Env.HTTP` вызывается через адаптер, а не напрямую. Тест исходников разрешает из `net/http` только
типы `Client`, `RoundTripper`, `Request`, `Response` и `ErrUseLastResponse`.

**Отмена.** Вернуть `context.WithValue(ctx, oauth2.HTTPClient, env.HTTP)`: отмена перестанет прерывать запрос.

## 4. Что считается ошибкой ввода, отказом и неподдерживаемым видом

- `ErrInvalidAnswer` (не тратит попытку, диалог остаётся открытым): пусто, не JSON, данные после документа, больше
  16 КиБ, `type` неизвестен или отсутствует, нет `client_email`, `private_key` не читается как PEM RSA (PKCS#8 или PKCS#1).
  Всё проверяется локально, без запроса к Google.
- `ErrUnsupported`: `external_account` (Workload Identity Federation), `external_account_authorized_user`,
  `authorized_user`, `impersonated_service_account`, `gdch_service_account`. Это валидные виды файлов Google, которые
  провайдер не обрабатывает. Список взят из констант `golang.org/x/oauth2/google` v0.37.0. Любой другой `type`
  это `ErrInvalidAnswer`.
- `ErrAnswerRejected` (тратит попытку): только `invalid_grant` от Google. Тело ответа разбирается самим провайдером:
  `jwt.Config` собирает `RetrieveError` без `ErrorCode`, так что полагаться на это поле нельзя.
- `ErrServiceUnavailable`: сетевые сбои, отказ политики адреса, HTTP 5xx и 429, ответ 2xx не в формате JSON.
- Остальные 4xx (`invalid_scope`, `unauthorized_client` и т. п.) это фиксированная ошибка `credGKETokenRequestRejected`
  без контрактного вида: повторять тот же ключ бессмысленно, и попытку это не тратит.

**Отмена.** Все соответствия собраны в `key.go` и `token.go` (`classify`).

## 5. Срок токена

Срок берётся из `expires_in` ответа. Он считается библиотекой от `time.Now()`, а не от `Env.Now`. Если `expires_in`
нет (Google его всегда присылает), срок равен `Env.Now() + 5 минут`. Утверждение (`exp - iat`) не превышает часа:
библиотека ставит `iat = now - 10 с`, `exp = iat + 1 час`; тест это проверяет.

## 6. Многострочное секретное поле в диалоге

**Решение.** В `ChallengeDialog` список многострочных полей явный (`MULTILINE_FIELDS` в `challengeView.ts`, пока
только `serviceAccountJson`). Такое поле рисуется маскированной `textarea` (`-webkit-text-security`, а не
`type=password`: он теряет переносы строк). Значение уходит только в `submit` (то есть в `AnswerChallenge`), не
сохраняется нигде и очищается при отклонённом ответе, смене вызова и закрытии диалога.

**Последствие.** По контракту `ErrInvalidAnswer` оставляет диалог открытым «с введённым значением», поэтому после такой
ошибки значение остаётся в поле, чтобы его можно было поправить. Очистка при закрытии и при `ErrAnswerRejected` остаётся.
Компонент общий для всех `secret-fields`, поэтому правка небольшая и не меняет поведение других полей.

**Отмена.** Убрать имя из `MULTILINE_FIELDS`: поле снова станет однострочным.

## 7. Вход пользователя Google (пункт 5 задачи): позже сделан, см. 2026-11-05-gke-user.md

Ниже записано состояние на 2026-11-04, когда пункт ещё не был сделан.

Пункт зависит от слияния промпта 8 и от подтверждения Vadim, что есть OAuth-клиент Google для Kubron. Подтверждения нет.
Отдельно проверено по документации Google (OAuth 2.0 for TV and Limited-Input Device Applications, страница обновлена
2026-10-16, раздел Allowed scopes): device flow поддерживает только `email`, `openid`, `profile`,
`drive.appdata`, `drive.file`, `youtube`, `youtube.readonly`. `cloud-platform` в списке нет, поэтому device flow для
GKE не реализуется. Остаётся вход через authcode с PKCE и браузерным возвратом: он ждёт тех же двух условий. Строка про
device flow в тикете B.7b неверна и требует правки.
