# Публичный origin для browser-callback

- Статус: ждёт ревью человеком
- Дата: 2026-11-04
- Область: B.3, серверная конфигурация OIDC browser-callback
- Связано: [ADR-0018](../adr/0018-cluster-auth-providers.md), [развёртывание](../deploy.md)

## Контекст

Для возврата браузера от OIDC-провайдера серверу нужен стабильный публичный origin Kubron.
Значение не должно браться из заголовков входящего запроса: Host и forwarded-заголовки могут
контролироваться клиентом или неверно настроенным прокси. Origin задаётся оператором явно.

## Решение

Сервер читает `KUBRON_PUBLIC_URL` из окружения и проверяет его при загрузке конфигурации:

- production URL должен использовать HTTPS;
- HTTP допускается только для `localhost`, поддоменов `.localhost` и loopback IP — для локальной разработки;
- значение должно быть абсолютным URL с host и не должно содержать userinfo, query, fragment или path;
- пустое значение означает, что browser-callback не настроен.

Публичный URL не добавляется в RPC/API и не выводится в логи. Для Helm переменная может быть передана
через существующий `kubron.extraEnv`; отдельное поле values не требуется.

## Последствия

- Callback redirect URI строится на основе доверенной конфигурации, а не недоверенного HTTP-запроса.
- Некорректная или небезопасная настройка приводит к отказу запуска, а не к незаметному downgrade на HTTP.
- Локальная разработка остаётся возможной без TLS на loopback.
- URL с path prefix не поддерживается: callback endpoint публикуется от корня origin.

## На ревью

Человеку необходимо подтвердить политику origin-only (без path prefix) и список loopback-форм,
разрешённых для HTTP. Этот документ фиксирует решение для реализации; статус не означает, что
весь поток browser-callback уже подключён.
