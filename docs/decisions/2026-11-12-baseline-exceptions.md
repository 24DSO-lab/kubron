# Решения: исключения baseline (ADR-0027)

Статус: **ждёт ревью человеком**.
Зона: `internal/baseline` (хранилище), `internal/drift` (сервис, применение при проверке).

## BX-01. Исключения хранятся отдельно от неизменяемой версии

- **Проблема.** ADR-0027 требует, чтобы версия была неизменяемой, и одновременно допускает исключения («это отклонение допустимо») с правкой и
  сроком. Если исключения лежат внутри версии, любое добавление исключения меняет версию.
- **Варианты.** (а) исключение внутри версии, правка создаёт новую версию: каждое исключение раздувает историю, срок действия не отразить;
  (б) исключения отдельной сущностью, привязанной к версии; (в) исключения на весь baseline вне версий: смена активной версии не меняет исключения,
  но тогда исключение может ссылаться на ресурс, которого в старой версии не было.
- **Решение.** (б). Один список исключений на версию (`PutExceptions`/`GetExceptions`). Содержимое версии (соль, объекты) не меняется никогда.
  При создании новой версии исключения активной версии копируются в неё; при возврате к старой версии действуют её собственные исключения.
- **Последствия.** Результат проверки перечисляет применённые исключения (с числом срабатываний) и просроченные, поэтому скрытое исключением
  изменение остаётся видимым. Исключение скрывает изменения по границе сегмента пути (`spec.replicas` не скрывает `spec.replicasX`).
  Просроченное исключение не применяется.
- **Отмена.** Хранить исключения внутри версии (вариант а): изменить `Version` и убрать таблицу `baseline_exceptions`.
