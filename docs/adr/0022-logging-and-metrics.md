# ADR-0022: Наблюдаемость: журнал процесса, аудит в stdout, метрики на отдельном порту

- Статус: принято
- Дата: 2026-11-05 (оформлен ретроспективно; журнал и аудит в stdout — 1.0.0, метрики — 0.6.0, см. CHANGELOG.md)
- Связано: ADR-0007, ADR-0016; docs/logging.md, docs/metrics.md, docs/archive/project-analysis-2026-10-27.md (раздел 4)

## Контекст

Анализ проекта (раздел 4): «`log/slog` не используется совсем, ошибки выводятся через `println`. Нужны структурированные логи: уровень, request-id и session-id в веб-режиме, вывод в файл для десктопа. Журнал аудита при этом остаётся отдельным.» Серверу с несколькими репликами (ADR-0016) нужны и метрики для Prometheus.

## Решение

**Журнал процесса.** `kubron-server` пишет `log/slog` в stderr, JSON по строке на запись. `KUBRON_LOG_LEVEL` (`debug|info|warn|error`, по умолчанию `info`), `KUBRON_LOG_FORMAT` (`json|text`, по умолчанию `json`); в чарте `kubron.logLevel`, `kubron.logFormat`. Неверное значение — сервер не стартует. Логгер задан как `slog.Default`, поэтому старый `log.Printf` тоже выходит JSON-ом. Код: `cmd/kubron-server/logging.go`, `internal/logging`.

**request_id.** Каждый HTTP-запрос получает `request_id` в записях и в заголовке `X-Request-Id`; входящий заголовок принимается только при 8–64 символах `A–Z a–z 0–9 . _ -`.

**Аудит — отдельный поток.** Основной журнал остаётся в хранилище (ADR-0007). `KUBRON_AUDIT_STDOUT=1` (чарт: `kubron.auditStdout`) дублирует записи строками JSON с `"type":"audit"` в stdout, журнал процесса — в stderr. Отказ зеркала на действие не влияет; для админ-команд (`rekey` и др.) оно не включается (`internal/audit/mirror.go`).

**Метрики.** `/metrics` на отдельном порту, по умолчанию выключено: `KUBRON_METRICS_LISTEN` / `--metrics-listen`, в чарте `metrics.enabled=false`, `metrics.port=9090`. Адрес не может совпадать с `KUBRON_LISTEN`; порт отдаёт только `GET /metrics`. Аутентификации нет, защита сетевая (отдельный Service, NetworkPolicy). Код: `cmd/kubron-server/metrics.go`, `internal/metrics`.

**Чего нет в журнале и метриках.** Каждая запись журнала (сообщение, атрибуты, тексты ошибок) проходит редактор, заменяющий на `[REDACTED]` чувствительные ключи, токены, заголовки авторизации, пароли в URL, JWT, PEM и известные серверу секреты (`KUBRON_SECRET_KEY`, пароли БД); `detail` аудита — тот же редактор; при фатальных ошибках пишется только класс ошибки. Метки метрик: имя RPC-метода из allowlist (иначе `unknown`), код ответа, состояние кластера из фиксированного набора, версия сборки. Имён пользователей, кластеров и пространств имён нет (`TestNoPrivateLabels`). Имя пользователя есть только в записях аудита.

## Рассмотренные альтернативы

Рассмотренные альтернативы в репозитории не зафиксированы. Известно лишь прежнее состояние: `println` и `log.Printf`.

## Последствия

- Редактор может скрыть и безобидный текст (`token: expired`); docs/logging.md называет это сознательным выбором.
- Метрики без аутентификации: безопасность держится на сетевых политиках; при внешнем Prometheus порт ограничивают самостоятельно.
- Счётчики обнуляются при перезапуске реплики; «на реплику» значения суммируются.
- Хранение аудита в stdout — на стороне внешнего сборщика.
- Идентификатор сессии в записях журнала и файл журнала на десктопе из анализа в коде и docs/logging.md не подтверждены.
