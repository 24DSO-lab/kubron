# ADR-0059: Машинные коды ошибок для решений клиента

- Статус: In Progress
- Дата: 2026-11-28
- Связано: ADR-0003 (веб-транспорт), ADR-0010 (слой platform/), ADR-0014 (локализация; не заменяется)

## Контекст

Веб-сервер уже отдаёт `{"error":{"code","message"}}` (`server.MapError`), но фронтенд принимал часть решений по
подстроке текста: `message.includes(...)`. В `i18n/backendErrors.ts` было семь таких констант (нет сессии,
учётные данные отклонены, вызов входа истёк, сохранённый вход недействителен, ввод непригоден, сервис входа
недоступен, не задан токен Argo CD). `platform/api.ts` и `IdleGuard.vue` проверяли `authentication required`
даже в веб-режиме, где код уже был.

Проблемы:

- Постороннее сообщение с той же подстрокой (текст реестра контейнеров или git: `unauthorized: authentication
  required`) выбрасывало пользователя из сессии. Регрессия закрыта тестом `platform/api.test.ts`.
- Переформулировка Go-ошибки молча ломала клиента: теста соответствия констант и Go не было.
- Нарушалось правило CONTRIBUTING (п. 4): решения по тексту ошибки не принимаются.
- Десктоп (Wails) отдаёт ошибку голой строкой, кода у неё не было.
- Веб отдавал для пяти ошибок входа в кластер общий код `error`: по коду их отличить было нельзя.

## Решение

1. Пакет `internal/apierr` без зависимостей (по образцу `publicerr`): `WithCode(code, err)` помечает ошибку
   кодом, `CodeOf(err)` читает его через `errors.As`. Текст и `errors.Is` не меняются. Типизированные ошибки
   могут сами реализовать `ErrorCode() string` (так сделан `k8s.ErrArgoTokenNotSet`).
2. Семь сентинелов получают коды, остаются объявлены через `errors.New` внутри `WithCode`, чтобы `i18n-check`
   по-прежнему видел их тексты:

   | Код | Ошибка |
   |---|---|
   | `unauthenticated` | `auth.ErrNotAuthenticated` |
   | `credential_rejected` | `credential.ErrAnswerRejected` |
   | `challenge_expired` | `credential.ErrChallengeExpired` |
   | `grant_invalid` | `credential.ErrInvalidGrant` |
   | `answer_invalid` | `credential.ErrInvalidAnswer` |
   | `auth_service_unavailable` | `credential.ErrServiceUnavailable` |
   | `argo_token_not_set` | `k8s.ErrArgoTokenNotSet` |

   Формат: нижний регистр с подчёркиванием, как у существующих кодов веба. Код стабилен: переименование
   ломает клиента.
3. `server.MapError` берёт код из `apierr.CodeOf`, если ни один прежний случай не подошёл. HTTP-статус не
   меняется (внутренняя ошибка, кроме `unauthenticated` → 401), JSON ответа тот же.
4. Десктоп: `options.App.ErrorFormatter` в `main.go` возвращает строку-конверт
   `{"v":1,"code":"…","message":"…"}` (`apierr.Envelope`). Ошибка без кода получает код `error`, как в вебе.
   Возвращать объект нельзя: JS-рантайм Wails превращает значение не-строку в `Error("[object Object]")`.
5. Фронтенд: `platform/apiError.ts` с `ApiError {code, message}` и `ERROR_CODES`. `RpcError` (веб) наследует
   `ApiError`. Единая точка нормализации — `callApp` (ADR-0010): конверт разбирается обратно в `ApiError`,
   любая другая ошибка пробрасывается как есть. Решения принимаются только через `hasErrorCode(e, …)`.
   `errorText(e)` по-прежнему возвращает `message`, поэтому локали и перевод по ADR-0014 не затронуты.
6. Соответствие проверяют тесты: `internal/server/apierr_codes_test.go` (каждый код имеет сентинел, веб и
   десктоп дают один код), `apierr_test.go` (формат конверта) и `platform/apiError.test.ts` (набор кодов
   зеркалирует Go).

## Рассмотренные альтернативы

- Коды вместо текстов целиком, в том числе для перевода: ADR-0014 отклонил как слишком дорогое. Здесь коды
  нужны только для решений; перевод остаётся по шаблонам сообщений.
- Объект из `ErrorFormatter`: см. п. 4, рантайм Wails теряет его.
- Префикс в тексте сообщения: ломает перевод по шаблонам и тесты на текст.
- Общий пакет, импортирующий все сентинелы: риск циклов импортов и связность слоёв.

## Последствия

- Новое решение клиента принимается только по коду: код добавляется в `apierr`, `ERROR_CODES` и в таблицу
  выше; тесты соответствия краснеют, если одна из сторон забыта.
- Тексты сообщений остаются английскими и переводятся по ADR-0014; менять их можно, не ломая клиента.
- Десктопная ошибка больше не является «голой строкой»: любой новый вызов привязок Wails в обход `callApp`
  покажет конверт как текст (ADR-0010 такие вызовы и так запрещает вне `src/platform/`).
- Не проверено вне CI: разбор конверта в запущенном десктопном приложении и в `wails dev` (там другой IPC).
  Нужна ручная проверка перед релизом.
