# ADR-0030: «Сообщить об ошибке»: приёмник отчётов и очередь вместо `mailto:`

- Статус: предложено
- Дата: 2026-11-10
- Заменяет: п. 3 ADR-0029 (десктоп через `mailto:`); остальное в ADR-0029 действует
- Связано: ADR-0008, 0029; код — `internal/bugreport` (`relay.go`, `outbox.go`), `internal/app/app_bugreport*.go`,
  `docs-site/functions/api/bugreport.ts`, `docs-site/relay/`, `docs/bug-report.md`

## Контекст

`mailto:` заставляет пользователя делать несколько действий: ждать, пока откроется почтовая программа, вставлять снимок
из буфера обмена, нажимать «Отправить» там. Нужно: нажать кнопку, написать описание, снимок прикладывается сам.
Ограничения: у пользователей может не быть аккаунта GitHub, а Kubron может стоять на сервере без выхода в интернет.
Отчёты могут содержать имена кластеров и значения Secret на снимке, поэтому публичный трекер не подходит.

## Решение

1. **Приёмник — Cloudflare Pages Function** `POST /api/bugreport` рядом с сайтом документации (`docs-site/functions`).
   Логика в `docs-site/relay/bugreport.ts` не зависит от среды Cloudflare (`fetch` и часы передаются параметрами) и
   проверяется обычным `node --test`.
2. **Хранение — приватный репозиторий отчётов.** Снимок кладётся файлом (Contents API), по отчёту создаётся issue со
   ссылкой на снимок. Токен GitHub (fine-grained, только этот репозиторий, права Contents и Issues) лежит в секретах
   Cloudflare; в приложении и в репозитории секретов нет.
3. **Защита анонимного адреса.** Те же проверки, что в приложении (описание до 5000 знаков, PNG по сигнатуре и размеру),
   лимит 10 отчётов в час с одного IP и 200 в сутки на всех (счётчики в KV). Без привязки KV приём закрыт.
4. **Клиент — Go-ядро.** Один запрос из `internal/bugreport/relay.go` (HTTPS, TLS 1.2+, таймауты, системный прокси).
   Десктоп использует приёмник проекта по умолчанию; сервер — только если администратор задал
   `KUBRON_BUGREPORT_RELAY_URL`. Значение `off` отключает приёмник.
5. **Цепочка каналов.** Сначала почтовый сервер, если он настроен (корпоративный SMTP работает без интернета),
   затем приёмник. Неверная настройка одного канала пропускается, пока есть другой.
6. **Очередь на диске.** Десктоп хранит отчёт, который не удалось доставить из-за отсутствия связи, в
   `<каталог данных>/bugreports/` (файл на отчёт, права 0600, не больше 20 штук, не старше 14 дней) и повторяет отправку
   через минуту после запуска и затем каждые 15 минут. Отказ приёмника (отчёт не принят) не повторяется: повтор ничего
   не изменит. Пользователь видит «Отправлено» или «Сохранено: уйдёт, когда появится связь».
7. **Экспорт архивом.** Для машины, откуда связи нет совсем, диалог показывает число ожидающих отчётов и кнопку
   «Сохранить архивом»: один zip, который передают разработчикам любым способом. Отчёты остаются в очереди.
8. **`mailto:` удалён**, вместе с буфером обмена для снимка и папкой черновиков.

## Рассмотренные альтернативы

- **Issue в публичном репозитории проекта.** Удобный трекер, но описание и снимок станут публичными сразу, а удалить
  их нельзя. Для Kubernetes-данных неприемлемо. Отклонено.
- **Отдельный сервис (VPS, контейнер).** Нужен свой хост с TLS и сопровождением. Pages Function уже рядом с сайтом
  документации и выкладывается тем же workflow.
- **Sentry или GlitchTip.** Хороши для автоматических отчётов о падениях, но тяжелее по зависимостям и согласию
  пользователя. Для кнопки «опишите проблему» избыточно; к ним можно вернуться отдельным решением.
- **Письмо через HTTP-API почтового сервиса.** Ещё один внешний сервис и ключ вместо GitHub, который и так нужен
  разработчику как трекер.
- **GitHub-аккаунт у пользователя.** Отклонено: у части пользователей его нет.

## Последствия

- Отчёт со снимком проходит через Cloudflare и GitHub. Диалог по-прежнему показывает снимок до отправки и
  предупреждает, что на нём могут быть секреты.
- Анонимный адрес можно засорять в пределах лимитов; при исчерпании квоты Cloudflare приём прекращается, а клиенты
  оставляют отчёты в очереди.
- Счётчики лимитов в KV приблизительные: для защиты от потока хватает, для точного учёта нет.
- Репозиторий отчётов должен быть приватным и содержать хотя бы один коммит; токен нужно перевыпускать раз в год.
- Деплой функции требует `workingDirectory: docs-site` в workflow, поэтому каталог `functions/` лежит там.
- Код приёмника на TypeScript, поэтому проверки отчёта дублируют `internal/bugreport/report.go`; расхождение пределов
  ловится тестами с обеих сторон.
