# ADR-0020: Защита HTTP-слоя kubron-server

- Статус: принято
- Дата: 2026-11-05 (оформлен ретроспективно; заголовки, token bucket и ограничение попыток — 0.4.0; allowlist Host — не позднее 1.0.0, см. CHANGELOG.md)
- Связано: ADR-0004, ADR-0016, `docs/http-security.md`, `docs/security-review.md`, `frontend/e2e/web-csp.spec.ts`

## Контекст

`kubron-server` открыт в сеть, часть вызовов анонимна (`Login`, `SetupAdmin`). Сессии, CSRF и `Origin` — в ADR-0004. В `docs/security-review.md` закрыты находки: подмена cookie соседним поддоменом (№4), сырые ошибки 500 (№7), нет allowlist Host (№8), порт в Host ломал маршрутизацию потоков port-forward (№9).

## Решение

Код — `internal/server`, `internal/auth`; подробности — `docs/http-security.md`.

- **Заголовки** на каждый ответ (`headers.go`): CSP со `script-src 'self'` без `unsafe-inline` и `unsafe-eval`; HSTS `max-age=31536000` только для защищённого запроса не на loopback; `Permissions-Policy`; COOP и CORP `same-origin`. `style-src` оставляет `'unsafe-inline'`: Monaco и xterm создают `<style>` на лету. CSP отдаёт только сервер, `KUBRON_CSP_REPORT_ONLY=1` включает Report-Only. Нарушения проверяет `web-csp.spec.ts`.
- **Cookie.** По защищённому каналу принимается только `__Host-kubron_session`; обычная игнорируется (cookie tossing).
- **`KUBRON_ALLOWED_HOSTS`**: список имён или IP, пусто — проверка выключена; другой Host получает `421` с одинаковым ответом; `/healthz` и `/readyz` исключены, потоки `*.pf.<домен>` разрешены автоматически. Чарт собирает список из `ingress.hosts` и `baseDomain`.
- **Статус 500.** Ошибки БД, сети, TLS, путей и таймаутов заменяются на `internal error, request id <id>`; подробности в журнале по `request_id`. Ошибки Kubernetes API, ввода и помеченные `server.PublicError` не скрываются.
- **Перебор входа:** 5 бесплатных попыток на логин и 30 на адрес клиента за 15 минут, затем экспоненциальная блокировка от 15 секунд до 5 минут. Так же считается `ChangePassword`; отказы идут в аудит. За прокси адрес берётся справа от `X-Forwarded-For`.
- **Анонимные RPC:** token bucket по адресу, 20 запросов сразу и 5 в секунду, ответ `429` с `Retry-After` (`ratelimit.go`).
- **Реплики** (ADR-0016): блокировка по логину общая, в таблице `login_failures` PostgreSQL. Счётчики по адресу и token bucket — в памяти реплики.

## Рассмотренные альтернативы

В репозитории зафиксированы только две:

- `<meta>`-тег CSP в `index.html` не использован: он затронул бы десктопную сборку Wails.
- Счётчики по адресу и token bucket в БД не вынесены: это дало бы запись на каждый запрос.

Остальные варианты не описаны.

## Последствия

- `style-src 'unsafe-inline'` остаётся, пока редактор и терминал создают стили на лету.
- Предел по адресу и для анонимных RPC — число реплик × порог; это грубое ограничение нагрузки, а не защита учётной записи.
- Если БД недоступна, блокировка по логину не проверяется (ошибка в журнале): сессию без БД не открыть.
- Причину скрытой ошибки 500 видно только в журнале по request id.
- Пустой `KUBRON_ALLOWED_HOSTS` отключает проверку Host.
