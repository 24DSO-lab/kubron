# Baseline конфигурации и дрейф (ADR-0027)

Baseline фиксирует нормализованное состояние выбранных ресурсов кластера. Проверка читает кластер, сравнивает его с активной версией
и показывает, что изменилось. Kubron **ничего не применяет и не исправляет**: нет отката к baseline, автоисправления, фоновых и периодических проверок.

## Что хранится

| Объект | Свойства |
|---|---|
| Baseline | имя, выборка (пространства имён, селектор меток, типы) или явный список ресурсов, активная версия |
| Версия | неизменяема; номер, версия правил (`RulesVersion`), автор, обязательный комментарий, соль, нормализованные объекты |
| Исключения | список на версию; редактируется отдельно от версии (см. [решение](decisions/2026-11-12-baseline-exceptions.md)) |
| Результат проверки | сводка, строки по ресурсам, применённые и просроченные исключения, оговорки |

Область (организация, команда, кластер) входит в ключ каждой записи. Запрос из другой области не видит данных; неполная область
отклоняется (fail closed).

## Поддерживаемые типы

Deployment, StatefulSet, DaemonSet, Service, Ingress, NetworkPolicy, ConfigMap. **Secret не поддерживаются и не читаются ни при каких условиях**
(даже если выбраны явно): ресурс получает статус «не проверено» с причиной `secret-unsupported`.

## Нормализация (RulesVersion = 1)

Два этапа: `normalizeTree` (идемпотентна) убирает служебные поля (`status`, `managedFields`, `resourceVersion`, `uid`, `generation`, аннотации
контроллеров и т.п.), значения по умолчанию и пустое, упорядочивает списки с ключами; затем `flatten` строит плоские пути «поле → значение».
Порядок init-контейнеров значим и сохраняется. `spec.replicas` у нагрузки под HorizontalPodAutoscaler исключается; если HPA прочитать не удалось,
в результате есть оговорка. При любом изменении правил `RulesVersion` растёт; версии со старыми правилами не сравниваются:
все их ресурсы получают «не проверено: rules-version-mismatch», нужна новая версия.

## Чувствительные значения

`ConfigMap.data` и `binaryData`, значения `env[].value`, а также любая строка, которую меняет редактор логов (ADR-0022), хранятся только как
HMAC-SHA256 с солью версии (32 случайных байта, шифруются вместе с версией). В результате проверки и в журнале нет самих значений:
только факт изменения и имя ключа. Сравнение через `hmac.Equal`. Типы `String`/`GoString`/`LogValue` у значений показывают `[HASHED]`.

## Источник изменения

Показывается только при доказательстве: запись `managedFields` (менеджер, время) либо запись аудита Kubron о применении YAML, время которой
совпадает с `managedFields` (допуск 30 с). Имя человека не показывается: оно требует права на аудит. Нет доказательства — нет источника.

## Создание версии

Только по явному действию: предпросмотр → комментарий → подтверждение «фиксируется текущее состояние, включая существующие отклонения».
Токен предпросмотра привязан к содержимому (HMAC ключом процесса) и действует 10 минут; если кластер изменился, создание отклоняется и нужен новый
предпросмотр. Пустая выборка не фиксируется. Новая версия становится активной; исключения активной версии переносятся на неё.

## Права

| Действие | Право |
|---|---|
| Просмотр, история, запуск проверки | `read` |
| Предпросмотр и создание версии, смена активной, исключения, удаление | `baseline.manage` |

## Хранилище и retention

Файловое (десктоп): `<данные>/baselines/<org>/<team>/<cluster>/<baseline>/…`, атомарная запись, права 0600/0700; не более 500 последних результатов на baseline.
PostgreSQL (сервер): миграция `0013_baselines`; версии шифруются secretbox (AAD: область, baseline, версия) и участвуют в `Rekey`, `RekeyReport`, keycheck.
После ротации ключа соль остаётся прежней, поэтому хеши остаются сравнимыми.

Задача в `internal/jobs`: результаты старше 90 дней удаляются; у каждого baseline сохраняются не менее 20 последних версий, активная — никогда.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `KUBRON_BASELINE_RESULTS_RETENTION_DAYS` | `90` | срок хранения результатов проверок |
| `KUBRON_BASELINE_MIN_VERSIONS` | `20` | сколько последних версий baseline сохранять (не меньше 20) |

## Проверка

```sh
go test -count=1 -race ./internal/baseline/... ./internal/drift/...
KUBRON_TEST_DATABASE_URL=postgres://… go test -count=1 -run Baseline ./internal/pgstore/
go test -run '^$' -fuzz FuzzNormalizeTree -fuzztime 30s -fuzzminimizetime 0 ./internal/drift/
```
