# Вход в кластеры: провайдеры учётных данных — тикеты

Цель: пользователь вставляет kubeconfig и подключается. Kubron сам определяет способ входа и просит только недостающее
(логин и пароль, вход в браузере, код устройства, ключи облака). Одинаково в десктопе и в вебе, безопасно по умолчанию.
Решение и обоснование: [ADR-0018](../adr/0018-cluster-auth-providers.md). Продолжает задачу 3.7 (этап 3).

## Сквозные решения

1. **Ошибка превращается в вызов.** `ConnectToCluster` возвращает результат `connected` или `challenge`; текстовые ошибки `ErrOIDCLoginRequired`
   и `ErrOIDCAuthCode` перестают быть тупиком. Интерфейс не выбирает способ входа, он рисует вызов по его виду.
2. **Личные данные для интерактивных входов, общие для статических** (ADR-0018, раздел 3). Пароль личной учётной записи не сохраняется.
3. **Один путь к `rest.Config`**: `ConfigFor(session, cluster)`. Пул подключений ключуется `(кластер, субъект)`.
4. **Произвольный `exec` в вебе не выполняется, песочницы нет.** Десктоп выполняет `exec` только после подтверждения пользователя;
   плагин используется, если найден в `PATH`, иначе нативный провайдер.
5. **Каждый провайдер независим**: добавление нового не меняет интерфейс и диалог.
6. Действуют правила `CONTRIBUTING.md`: заголовки лицензии, DCO, тексты ошибок Go на английском с записью в `backend.json` всех языков
   (`en`, `ru`, `cn`), интерфейс только через ключи i18n, `node scripts/i18n-check.mjs`, `gofmt -l .`, `go vet ./... && go test ./...`.

## Итого и порядок

Фаза A ≈ 44 ч-д, фаза B ≈ 52 ч-д, фаза C ≈ 21 ч-д. Всего ≈ 117 ч-д (без тикетов каталога B.7d сверх первых 2 ч-д); оценка предварительная, уточняется после A.1–A.3.

Порядок: A.1–A.4 → A.5 с B.1 (первая вертикаль: ввод логина и пароля для существующих кластеров, закрывает ошибку «enter a login and password») →
A.6–A.8 → C.1 → B.3–B.4, B.2 (закрывает «browser sign-in») → B.5–B.6, B.8–B.9 → A.9–A.10 → B.7a (EKS), B.7b (GKE), B.7c (AKS) → C.2–C.5.

## Решения владельца продукта (2026-11-02)

1. Десктоп: плагин `exec`, если найден в `PATH` (после подтверждения), иначе нативный провайдер.
2. Порядок облачных провайдеров: EKS, GKE, AKS.
3. Песочницы `exec` в вебе нет и не будет; тикет B.10 снят.
4. Выбор библиотеки keyring и ключа без PostgreSQL поручен реализатору: см. `docs/decisions/2026-11-02-cluster-auth.md` (ждёт ревью человеком).

## Статус (после фазы 2)

Завершающая серия (ветка `feat/cred-finish`, пункты 1.1–1.7 и 2.1–2.4) выполнена; CI зелёный до 2.4 включительно, для 2.1–2.3 запущен. C.4 (e2e с Keycloak и kind) остаётся открытым. B.1 завершён задачей 2.1: «общая учётная запись команды»

`verifyOIDCLogin`, `ErrOIDCLoginRequired`, `ErrOIDCAuthCode`, `ErrExecForbidden`, `checkExecAllowed`, `App.ConnectToCluster`, `internal/oidcpassword`, `cmd/oidc-spike`).

Ждёт человека: [B.3 security decision](../decisions/2026-11-04-oidc-browser-callback.md) и решение D-01/D-02. Статус ADR-0018 не менялся.

### Известные ограничения

- В вебе ссылки kubeconfig на файлы IdP (CA и т. п.) молча игнорируются, а не отклоняются.
- Для Dex нужен `offline_access`, IdP по `http` в серверном режиме не работает (см. `docs/deploy.md`, «Вход в кластеры: что настроить в IdP»).
- Ручная приёмка в веб-режиме на двух kubeconfig (3.1) и e2e с Keycloak и kind (3.2) требуют окружения пользователя и не выполнялись в песочнице.
