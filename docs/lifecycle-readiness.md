# Готовность к обновлению Kubernetes (Upgrade Readiness)

Реализация [ADR-0025](adr/0025-kubron-lifecycle.md). Раздел **«Готовность к обновлению»** (группа «Конфигурация» в боковом меню) оценивает, готов ли выбранный кластер к обновлению Kubernetes. Kubron **только читает** кластер и ничего в нём не меняет: обновление не выполняется и не запускается.

Отчёт — оценка, а не гарантия. Всё, что проверить не удалось, называется «не проверено» и никогда не превращается в «совместимо».

## Что проверяется

Режим один: **общий Kubernetes** (`generic-kubernetes`). Проверок конкретных провайдеров (EKS, GKE, AKS и др.) нет, и отчёт об этом прямо говорит.

| Область | Как | Статусы |
|---|---|---|
| Устаревшие и удалённые API | живые объекты кластера: `managedFields[].apiVersion` и аннотация `kubectl.kubernetes.io/last-applied-configuration`; сравнение со встроенной матрицей | `deprecated`, `removed` |
| Компоненты | каталог: kubelet (по объектам Node, version skew), системные нагрузки (Deployment, DaemonSet, StatefulSet) | `confirmed`, `known_limitation`, `insufficient_data`, `not_recognized` |
| Путь обновления | шаги минорных версий (больше одной — предупреждение), текущая версия вне окна апстрима | `ok`, `attention` |
| Источники | недоступный, запрещённый или обрезанный источник — отдельное предупреждение | `not_checked`, `partial` |

Важность: `blocker` (API удалён в целевой версии), `warning`, `info`. Нездоровый компонент даёт важность не ниже `warning`. Неизвестная версия или сочетание не бывает `confirmed`.

Без целевой версии API оцениваются относительно текущей: сообщаются только уже устаревшие.

### Что не проверяется (и записано в coverage)

- манифесты GitOps (Argo CD, Flux, Git) и локальные файлы — источники названы «не проверено» с причиной;
- клиенты, которые API только читают (контроллеры, скрипты), и объекты без `managedFields`/`last-applied`;
- пользовательские ресурсы, релизы Helm, шаблоны чартов;
- виды API, которые платформа не вправе читать (allowlist; Secret — никогда): они перечисляются в `coverage.notCovered`.

## Поле coverage

Обязательно в каждом отчёте. Отчёт без заполненного coverage не проходит `Report.Validate`, не сохраняется и не экспортируется. В coverage: режим, версия, относительно которой оценены API, **все три источника** (проверенные и нет, с причиной), методы, просмотренные и не охваченные виды API, версия и дата матрицы API и каталога, общие ограничения. Интерфейс показывает coverage раньше находок.

## Матрица API

`internal/readiness/apimatrix/matrix.json` — встроена в бинарник, версионируется (`version` зависит от содержимого), при загрузке проверяется. Источник — файлы `zz_generated.prerelease-lifecycle.go` репозитория `kubernetes/kubernetes` по тегам релизов. Окно целей — три последние поддерживаемые минорные версии (по расписанию релизов kubernetes.io). Версия кластера новее матрицы — в coverage предупреждение «матрица устарела для этого кластера».

### Порядок обновления матрицы (при выходе новой минорной версии)

1. `go run ./scripts/gen-apimatrix -cache .cache` (нужен доступ к raw.githubusercontent.com; в сборке и при проверке отчёта сеть не используется). Скрипт перечитывает теги и расписание, обновляет окно и `matrix.json`.
2. `go run ./scripts/gen-apimatrix -check` — файл совпадает с апстримом.
3. `go test ./internal/readiness/...` — тесты сверяют фикстуры окна с матрицей.
4. Обновить `internal/readiness/catalog/components.yaml` (правила совместимости, `checkedAt`) по документации проектов.
5. Строка в `CHANGELOG.md`, коммит.

## Каталог компонентов

`internal/readiness/catalog/components.yaml`: у каждого компонента ссылка `docs` на документацию совместимости проекта и дата проверки `checkedAt`; они видны в отчёте. Правило может только подтвердить совместимость или назвать ограничение; если данных нет — `insufficient_data`. Нераспознанная системная нагрузка — `not_recognized` (info).

## История и сравнение

Каждая проверка сохраняется: файловое хранилище (`<каталог данных>/readiness`, права 0600/0700, атомарная запись) или PostgreSQL (таблица `readiness_reports`, миграция 0012). Область (`tenant.Scope`) входит в каждый ключ и запрос; чужая область отвечает как «не найдено». История идёт постранично, новые первыми. Новый отчёт сравнивается с предыдущим: новые, устранённые и изменившиеся находки; при разных целевых версиях или версиях матриц это указано.

Хранение (`KUBRON_READINESS_*`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `KUBRON_READINESS_KEEP_PER_CLUSTER` | `50` | отчётов на кластер; `0` — без ограничения |
| `KUBRON_READINESS_MAX_AGE` | `180d` | возраст отчёта (`24h` и больше; `0` — без ограничения) |

Очистка идёт фоновой задачей; в серверном режиме с PostgreSQL — под advisory lock.

## Экспорт

JSON (`{format, report}`) и Markdown; в обоих есть раздел coverage. Markdown на английском. В веб-версии файл скачивается, в десктопе содержимое копируется в буфер обмена.

## Права и аудит

Все методы — право `read` на кластер. Чтение идёт через платформу (ADR-0026): allowlist видов, deadline, лимит одновременных чтений. Аудит: `ReadinessRun`, `ReadinessExport` (имя действия — «модуль + операция», как у отказа по праву); содержимое объектов и значения секретов не читаются и не попадают в журналы и отчёты — только идентификаторы, версии и счётчики.

## RPC

`ReadinessInfo`, `ReadinessRun(clusterID, target)`, `ReadinessHistory(clusterID, cursor, limit)`, `ReadinessGet(clusterID, id)`, `ReadinessCompare(clusterID, id, previousID)`, `ReadinessExport(clusterID, id, format)`.

## Что не входит

Выполнение обновления, drift и baseline (ADR-0027), API провайдеров, анализ манифестов GitOps, резервное копирование, compliance, календарь окон обслуживания.
