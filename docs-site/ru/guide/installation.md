# Требования, загрузка и проверка

Kubron выпускается в двух версиях: **Desktop** и **Web**. Выберите подходящую и следуйте соответствующему руководству. На этой странице собраны требования, таблица файлов и шаги проверки, общие для обеих.

| Я хочу… | Редакция | Руководство |
|---|---|---|
| Управлять кластерами со своего компьютера | **Desktop** | [Desktop-версия](/ru/guide/desktop) |
| Попробовать веб-интерфейс у себя | **Web, пробный запуск** | [Локальный быстрый старт](/ru/server/quick-start) |
| Дать команде доступ к кластерам через браузер | **Web, продакшн** | [Развёртывание в Docker и Kubernetes](/ru/server/deploy) |
| Собрать Kubron самому или участвовать в разработке | **Из исходников** | [Сборка из исходников](/ru/guide/build-from-source) |

## Системные требования

### Desktop

| Платформа | Поддерживается | Дополнительно |
|---|---|---|
| Windows | Windows 10 и 11, 64-разрядная (x64) | Microsoft Edge **WebView2 Runtime** (предустановлен в Windows 11 и актуальной Windows 10) |
| macOS | Apple Silicon и Intel (одна универсальная сборка) | Ничего |
| Linux | 64-разрядный (x86-64) с графическим окружением | **GTK 3** и **WebKitGTK 4.1** (`libwebkit2gtk-4.1`) |

Для всех платформ:

- Сетевой доступ с вашей машины до API-серверов Kubernetes, которыми вы хотите управлять.
- Kubeconfig (или данные для его создания). В Azure AKS, AWS EKS и Google GKE Kubron входит сам. Для любого другого `exec`-плагина команда должна быть установлена и доступна в `PATH`, а запуск вы подтверждаете в Kubron.
- `kubectl` **не нужен**. Kubron обращается к API Kubernetes сам.

::: info Сборки для Linux
Релизные сборки делаются и проверяются на Ubuntu 24.04. WebKitGTK 4.1 есть и в Debian 12. Сборки для arm64 под Linux и Windows не публикуются.
:::

### Web-версия (сервер)

| Компонент | Требование |
|---|---|
| PostgreSQL | **14 или новее.** Нужен для продакшна и многопользовательской работы. Миграции применяются автоматически при старте |
| Ключ шифрования | 32 случайных байта в формате `id:base64`, хранится в вашем менеджере секретов |
| TLS | Обратный прокси или ingress, который терминирует TLS. Сам сервер этого не делает |
| Kubernetes (для Helm-чарта) | **1.27 или новее** |
| Helm (для чарта) | Helm 3 с поддержкой OCI |
| Среда запуска контейнеров | Любая OCI-совместимая для опубликованного образа (`linux`, не-root пользователь `65532`) |

## Загрузка

Все десктопные сборки публикуются на странице [Releases](https://github.com/24DSO-lab/kubron/releases).

| Платформа | Файл | Содержимое |
|---|---|---|
| Windows (x64) | `Kubron_v<версия>_windows-amd64.zip` | `Kubron.exe` |
| macOS (универсальная) | `Kubron_v<версия>_macos-universal.zip` | `Kubron.app` |
| Linux (x64) | `Kubron_v<версия>_linux-amd64.tar.gz` | Исполняемый файл `Kubron` |
| Debian / Ubuntu (x64) | `kubron_<версия>_amd64.deb` | Пакет с пунктом меню и иконкой |
| Все | `SHA256SUMS.txt` | Контрольные суммы всех файлов |
| Все | `kubron-sbom_v<версия>_desktop.cdx.json`, `kubron-sbom_<версия>_image.spdx.json`, `kubron-sbom_<версия>_chart.cdx.json` | Спецификации состава ПО для десктопных файлов, образа сервера и Helm-чарта (`v` есть только в имени десктопного файла) |

Например, версия 1.0.0 — это `Kubron_v1.0.0_windows-amd64.zip` и `kubron_1.0.0_amd64.deb`. Обратите внимание: в именах архивов есть `v` из тега релиза, а в имени `.deb` его нет.

Релиз-кандидаты (версии вида `1.1.0-rc.1`) помечаются на GitHub как pre-release. Если вы не тестируете, берите последнюю версию без этой пометки.

## Проверка загрузки

Сборки пока не подписаны сертификатом, поэтому рекомендуем проверять файлы самостоятельно. Это занимает меньше минуты.

### 1. Проверьте контрольную сумму

Скачайте `SHA256SUMS.txt` в ту же папку, что и файл.

::: code-group

```bash [Linux]
sha256sum --check --ignore-missing SHA256SUMS.txt
```

```bash [macOS]
shasum -a 256 --check --ignore-missing SHA256SUMS.txt
```

```powershell [Windows (PowerShell)]
(Get-FileHash .\Kubron_v1.0.0_windows-amd64.zip -Algorithm SHA256).Hash
# Сравните результат с соответствующей строкой в SHA256SUMS.txt (регистр не важен)
```

:::

Рядом с именем файла должно стоять `OK`. Если видите `FAILED`, удалите файл и скачайте заново.

### 2. Проверьте происхождение сборки

К каждому десктопному файлу прилагается подписанная аттестация, связывающая его с конкретным коммитом и запуском GitHub Actions, который его собрал. При установленном [GitHub CLI](https://cli.github.com/):

```bash
gh attestation verify Kubron_v1.0.0_linux-amd64.tar.gz --repo 24DSO-lab/kubron
```

Успешный запуск выведет workflow, создавший файл. То же работает для `.deb` и для архивов Windows и macOS.

## О предупреждениях для неподписанных сборок

Поскольку сборки не подписаны сертификатом, при первом запуске операционная система предупредит вас. Это ожидаемо. Предупреждения и способ продолжить описаны для каждой платформы в разделе [Desktop-версия](/ru/guide/desktop#если-что-то-не-работает). Если вы вообще не хотите доверять готовому бинарнику, [соберите Kubron из исходников](/ru/guide/build-from-source).
