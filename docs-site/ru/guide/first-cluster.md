# Первый кластер

После [установки Kubron](/ru/guide/desktop) и создания локального администратора приложение пусто, пока вы не добавите кластер.

## Что понадобится

Нужен способ подключиться к кластеру:

- файл **kubeconfig**. По умолчанию это `~/.kube/config` (в Windows `%USERPROFILE%\.kube\config`) или то, на что указывает переменная `KUBECONFIG`;
- сетевой доступ с вашего компьютера до API-сервера кластера (VPN, правила бастиона и т. п. — на вашей стороне);
- если kubeconfig использует `exec`-плагин, который Kubron не обрабатывает сам, эта команда должна быть установлена и доступна в `PATH`. В Azure AKS, AWS EKS и Google GKE Kubron входит сам; для любого другого плагина он показывает команду и просит подтвердить запуск. См. [Подключение к Kubernetes](/ru/features/cluster-auth).

Проверьте любым привычным способом: если `kubectl get nodes` работает, заработает и Kubron. Сам Kubron `kubectl` не требует.

## Добавление кластера

1. Откройте **Settings → Clusters** или переключатель кластеров и выберите **Add cluster** (добавить кластер).
2. Задайте **имя**, например `Production EU`.
3. В разделе **Connection** (подключение) выберите **источник kubeconfig**:
   - **File** — выберите файл kubeconfig;
   - **Paste text** — вставьте содержимое kubeconfig.
4. В разделе **Appearance** (внешний вид) задайте необязательные **цвет**, **иконку** и **тег окружения** (`dev`, `test`, `stage`, `prod`). Они видны везде, поэтому выполнить команду на проде по ошибке гораздо сложнее.
5. *(Необязательно)* Если Argo CD в кластере опубликован через Ingress, укажите его адрес: Kubron откроет его напрямую вместо проброса порта.
6. Нажмите **Add cluster**.

Kubron копирует содержимое kubeconfig в собственный каталог, доступный только вам; исходный `~/.kube/config` не изменяется. Если позже вы измените исходный файл, замените сохранённую копию в настройках кластера.

::: tip Несколько контекстов в одном файле
Если в kubeconfig несколько контекстов, добавьте кластер по разу на каждый контекст и дайте им понятные имена и теги.
:::

## Ограниченный доступ? Всё равно работает

Kubron не требует cluster-wide права `list`. Если вам доступны только некоторые namespace, ограничьте набор namespace в настройках кластера. Kubron покажет то, что вам разрешено, и сообщит, что прочитать не удалось, вместо пустого экрана.

## Что вы получите

Kubron использует shared informers, поэтому списки и дашборд остаются актуальными без агрессивного опроса API-сервера. Откройте [дашборд](/ru/features/dashboard): состояние, проблемные Pod и недавние изменения, либо [ресурсы](/ru/features/resources).

## Несколько кластеров

Держите сколько угодно кластеров и переключайтесь между ними из одного окна. У каждого кластера свой фильтр namespace и состояние представлений.

## Если что-то не работает

| Симптом | Вероятная причина |
|---|---|
| Проверка подключения завершается по таймауту | API-сервер недоступен с вашего компьютера: VPN, файрвол или прокси |
| `x509: certificate signed by unknown authority` | В kubeconfig нет CA кластера либо корпоративный прокси подменяет TLS-сертификат |
| `Unauthorized` или `Forbidden` | Истёк токен или у пользователя не хватает прав RBAC |
| Появилось окно входа | Кластеру нужен интерактивный вход (OIDC, AKS, EKS, GKE или `exec`-плагин). Следуйте окну; см. [Подключение к Kubernetes](/ru/features/cluster-auth) |
| Падает `exec`-плагин | Команда плагина не установлена или не находится в `PATH`, который видит приложение (см. [Desktop-версия](/ru/guide/desktop#если-что-то-не-работает)) |

Используете Web-версию? Правила для kubeconfig там другие: см. [Подключение к Kubernetes](/ru/features/cluster-auth#web) и [локальный быстрый старт](/ru/server/quick-start#добавление-первого-кластера).
