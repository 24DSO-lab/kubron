# Версия и обновления

Kubron показывает свою версию, раз в сутки проверяет, не вышел ли новый релиз, и подсказывает администраторам, как именно обновиться при вашем способе установки. **Kubron сам обновления не устанавливает:** он показывает шаги, а выполняете их вы.

[[toc]]

## Где видна версия

Текущая версия показана в шапке. Её видит каждый вошедший пользователь, поэтому её удобно называть в обращении в поддержку. Если вышел новый релиз, администраторы видят там **Update available: 1.3.0** и баннер: **Kubron 1.3.0 is available (installed: 1.2.0)**. **How to update** открывает окно **Version and updates**, а **Hide until the next version** убирает баннер. Скрытие запоминается в браузере или окне и действует до выхода более новой версии.

Подробности об обновлениях видят только **администраторы** (право `users.manage`), потому что способ установки и имя релиза Helm описывают ваше развёртывание. Остальным пользователям показана только версия.

## Как работает проверка

- Раз в сутки Kubron спрашивает GitHub (`api.github.com`) о **последнем стабильном релизе** проекта. Черновики и pre-release игнорируются.
- Первая проверка выполняется примерно через 30 секунд после запуска, поэтому запуск никогда не ждёт сеть. После сбоя Kubron повторяет попытку через час.
- **Check for updates** в окне запускает проверку сразу. Кнопка доступна администраторам и ограничена одним разом в минуту; в течение этой минуты показывается последний известный результат.
- Запросы условные (`ETag`), поэтому неизменившийся ответ не расходует лимит запросов GitHub, а токен Kubron не отправляет.
- Сборка для разработки (собранная из исходников без версии) не проверяется: ей не с чем сравнивать. Окно сообщает об этом.

Единственный сервер, к которому Kubron при этом обращается, — GitHub. GitHub видит ваш IP-адрес и `User-Agent` с версией Kubron. Сведения о ваших кластерах и пользователях не отправляются.

## Окно «Version and updates»

| Поле | Значение |
|---|---|
| **Installed version** | Версия, которую вы запускаете |
| **Installation** | Как установлена эта копия (см. ниже) |
| **Latest version** | Новейший стабильный релиз |
| **Last checked** | Когда завершилась последняя проверка |

В разделе **How to update** окно показывает шаги для вашего способа установки: кнопку **Download** для десктопных файлов, команды с кнопкой **Copy** и **Release notes on GitHub**. Для десктопных загрузок есть и ссылка на `SHA256SUMS.txt`, чтобы вы могли [проверить файл](/ru/guide/installation#проверка-загрузки).

## Шаги для каждого способа установки

| Установка | Что показывает окно |
|---|---|
| **Helm-чарт** | `helm upgrade <релиз> oci://ghcr.io/24dso-lab/charts/kubron --version <новая> --namespace <namespace> --reset-then-reuse-values`. Ваши текущие значения сохраняются, а новые значения чарта по умолчанию применяются. Имя релиза и namespace берутся из чарта (для `--reset-then-reuse-values` нужен Helm 3.14 или новее) |
| **Kubernetes (без Helm)** | Тег нового образа, `ghcr.io/24dso-lab/kubron:<новая>`: измените его в манифестах, Kustomize или репозитории GitOps и примените |
| **Контейнер (Docker, Podman)** | `docker pull ghcr.io/24dso-lab/kubron:<новая>` и `docker compose pull && docker compose up -d` |
| **Серверный бинарник** | Замените бинарник новой сборкой и перезапустите его. В окне есть ссылка на релиз |
| **Пакет DEB** | Скачайте `.deb` и выполните `sudo apt install ./kubron_<новая>_amd64.deb`. Новая версия начнёт работать после перезапуска приложения |
| **Архив** (Windows `.zip`, Linux `.tar.gz`) | Скачайте новый архив и замените файлы текущей установки |
| **Приложение macOS** | Скачайте новый архив и замените `Kubron.app` в Программах |
| **Неизвестно** | Окно не смогло определить, как установлен Kubron, поэтому показывает ссылку на страницу релиза, а не неверную команду |

Перед обновлением Web-сервера сделайте резервную копию и прочитайте [замечания об обновлении](/ru/server/deploy#обновление).

### Как определяется способ установки

- **Helm-чарт:** чарт сообщает серверу (`KUBRON_INSTALL_METHOD=helm`, с именем релиза и namespace).
- **Kubernetes без Helm** и **контейнеры:** сервер узнаёт Pod или контейнер по окружению.
- **Пакет DEB:** Kubron проверяет, что файл принадлежит установленному пакету `kubron`.
- Если автоопределение ошиблось, например когда образ запущен вашим оркестратором, задайте `KUBRON_INSTALL_METHOD` равным `helm`, `kubernetes`, `docker` или `binary`.

## Отключение проверки

| Версия | Как |
|---|---|
| **Desktop** | В окне снимите флажок **Check for updates automatically once a day**. **Check for updates** по-прежнему работает по запросу. Выбор сохраняется в `updates.json` в [папке данных](/ru/guide/desktop#где-kubron-хранит-данные) |
| **Web** | Задайте `KUBRON_UPDATE_CHECK=off` либо `kubron.updateCheck: false` в Helm-чарте. Сервер перестаёт обращаться к GitHub, а окно сообщает, что проверку отключил администратор. Любое значение, кроме `on` и `off`, останавливает запуск сервера, поэтому опечатка не оставит проверку включённой случайно |

Отключайте её в изолированных сетях. В Web-версии изменить эту настройку из интерфейса нельзя.

## Доступ к сети {#network-access}

Для проверки нужен HTTPS до `api.github.com`. В Helm-чарте правило исходящего трафика к API-серверам по умолчанию пропускает порт 443 на любые адреса, поэтому GitHub доступен. Если вы сузили `networkPolicy.egress.clusterApi.cidrs`, добавьте правило для `api.github.com` в `networkPolicy.egress.extra` либо отключите проверку; иначе окно покажет сетевую ошибку. См. [Развёртывание в Docker и Kubernetes](/ru/server/deploy#update-check).

## Сообщения

| Сообщение | Значение |
|---|---|
| **Could not reach GitHub. Check the network connection.** | Нет сетевого пути до `api.github.com`: прокси, файрвол или `NetworkPolicy` |
| **GitHub request limit exceeded. Try again later.** | Лимит GitHub для вашего адреса исчерпан. Запросы анонимные и ограничены по адресу, ежедневная проверка редко его достигает |
| **No releases have been published yet.** | В репозитории нет стабильных релизов |
| **GitHub returned an unexpected response.** | Ответ не похож на релиз |
| **Update checks are turned off by the administrator of this installation.** | `KUBRON_UPDATE_CHECK=off` |
| **This is a development build: update checks are disabled.** | Сборка без версии релиза |
| **Details about updates are available to administrators.** | Вы не администратор |
