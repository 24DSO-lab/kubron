# Команды и совместный доступ

Управление командами доступно в Web-версии при подключённом PostgreSQL. Оно не входит в Desktop и Web-режим с файловым хранилищем одного пользователя.

Например:

```
Организация
├── Команда «DevOps»        Alice (admin), Bob (operator)
│   ├── кластер Production
│   └── кластер Staging
└── Команда «Development»   Carol (operator), Dan (user)
    └── кластер Dev
```

Участники видят кластеры только своих команд и действуют в них с ролью, которая у них есть в каждой команде. Alice работает с Production и Staging, но не с Dev, если она не состоит ещё и в «Development».

## Организация → команда → кластер

Kubron использует простую модель владения:

- организация содержит команды;
- пользователи входят в одну или несколько команд;
- каждый кластер принадлежит ровно одной команде;
- роль пользователя назначается отдельно в каждой команде.

Участник видит и обслуживает только кластеры команд, в которые он входит. Администратор организации может управлять пользователями и командами, но не получает автоматический доступ к данным кластеров без членства в соответствующей команде.

## Управление командами

Администраторы организации (с правом `users.manage`) могут создавать, переименовывать и удалять команды, управлять пользователями организации и назначать членство в командах. Администратор команды тоже может переименовать свою команду и управляет участниками и кластерами своей команды.

Администратор команды может:

- добавить кластер в команду, в том числе кластер, в котором работает сам Kubron (под ServiceAccount сервера);
- изменить подключение и отображаемые настройки кластера;
- управлять участниками и ролями команды в рамках правил организации.

Удалить можно только пустую команду: сначала перенесите или удалите её кластеры. Перенос кластера в другую команду — отдельная операция, для которой нужны права администратора и в текущей, и в новой команде.

## Роли в команде

В Kubron есть три встроенные роли:

| Роль | Доступ |
|---|---|
| `admin` | Полный доступ в рамках команды, включая управление её участниками и кластерами, привилегированные операции |
| `operator` | Просмотр, значения Secret и безопасные операции с workloads: scale, restart, rollback |
| `user` | Только чтение; без значений Secret и привилегированных операций |

Права проверяются на backend, а не только скрытием кнопок в интерфейсе. Дополнительно действует Kubernetes RBAC: разрешение Kubron не расширяет права учётных данных, которыми выполняется запрос к Kubernetes API.

## Изоляция

При каждой операции над кластером приложение проверяет членство пользователя в команде-владельце. Чужой кластер не появляется в списках и не становится доступен при подборе его идентификатора. Helm-репозитории, учётные данные OCI и журнал Helm-операций в PostgreSQL также разделены по командам.

См. [Безопасность и управление доступом](/ru/features/security) и [Развёртывание Web](/ru/server/deploy).
