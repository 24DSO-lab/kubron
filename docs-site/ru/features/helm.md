# Helm

Kubron включает инструменты Helm для управления релизами и источниками чартов прямо в рабочем пространстве Kubernetes.

## Релизы

- Просмотр релизов активного кластера и их статусов.
- Просмотр values, отрендеренных manifest и notes чарта (при наличии `secrets.read`).
- История ревизий и сравнение двух ревизий.
- Откат к предыдущей ревизии и удаление релиза с возможностью сохранить историю.

## Права

Установка, обновление и удаление релизов требуют права Kubron `write`. Откат релиза требует `operate`. Чтение values, manifest, diff ревизий и предпросмотр обновления требуют `secrets.read`, потому что в них могут быть секреты. Добавление и удаление репозиториев и OCI-реестров требует `clusters.manage`. См. [справочник прав](/ru/features/security#справочник-прав).

## Каталог чартов и репозитории

- Добавление, обновление и удаление HTTP chart repositories.
- Использование репозиториев с basic authentication.
- Поиск чартов и просмотр доступных версий.
- Добавление OCI registry и выбор опубликованных в них чартов.
- Настройка TLS-поведения репозитория, где это поддерживается; отключать проверку сертификата следует только в доверенной среде.

## Безопасная установка и обновление

- Предварительный dry-run установки или обновления.
- Просмотр diff отрендеренного manifest перед применением.
- Отправная точка — текущие пользовательские values релиза: их можно отредактировать или изменить только версию чарта. Отправленные values заменяют прежние целиком, поэтому ключ, удалённый в редакторе, возвращается к значению по умолчанию из чарта.
- Отслеживание хода операции и просмотр журнала последних Helm-операций.
- Проверка наличия новой версии чарта для установленного релиза.

## Хранение в Desktop и Web

Desktop и Web с файловым хранилищем одного пользователя сохраняют конфигурацию Helm в локальном каталоге данных Kubron. В Web team mode с PostgreSQL репозитории, зашифрованные учётные данные и журнал Helm-операций хранятся отдельно для каждой команды и доступны репликам сервера. Кэш остаётся воспроизводимыми локальными данными.

Web применяет сетевую политику к исходящим запросам к chart repositories и OCI registry для снижения SSRF-риска. Для приватных или внутренних адресов репозиториев может потребоваться явный allowlist администратора; см. [конфигурацию сервера](/ru/server/configuration).
