# Подключение к Kubernetes

Kubron читает контексты kubeconfig и использует учётные данные выбранного контекста. Вручную выбирать режим подключения не требуется.

## Desktop

Desktop работает на вашем компьютере и подключается к Kubernetes API с этого же компьютера.

- Импортируйте kubeconfig-файл или вставьте его содержимое.
- Выберите контекст, если в kubeconfig их несколько.
- Поддерживаются статические учётные данные, например токен и клиентский сертификат.
- Exec credential plugins Kubernetes могут запускаться локально, если соответствующий плагин установлен на вашем компьютере.

Exec-плагин — исполняемый код. Импортируйте kubeconfig только из доверенных источников.

## Web

Web-сервер подключается к кластерам из собственной сетевой среды сервера. Он не может читать файлы с вашего компьютера и не запускает произвольные команды из загруженного kubeconfig.

Сейчас Web поддерживает следующие варианты подключения:

- статические учётные данные, встроенные в kubeconfig, например токен или клиентский сертификат;
- поддерживаемый сценарий `oidc-login` с password grant, где пользователь вводит необходимые учётные данные;
- ServiceAccount самого сервера, если Kubron развёрнут внутри Kubernetes и доступна сервисная конфигурация с командами.

Web отклоняет kubeconfig, который ссылается на локальные файлы, требует произвольную команду `exec` или использует browser-based `oidc-login`, который текущий Web flow завершить не может. Не ожидайте, что сервер запустит плагин, установленный только на вашем ноутбуке.

> **Важно о текущем объёме:** архитектура провайдеров учётных данных описывает более широкий набор OIDC- и cloud-provider-сценариев, но пока не подключена к текущему RPC и интерфейсу приложения. Список выше описывает реализованные способы подключения, а не полный будущий дизайн провайдеров.

## Два уровня разрешений

В Web team mode доступ определяется пересечением:

1. разрешений Kubron, назначенных ролью пользователя в команде-владельце кластера;
2. Kubernetes RBAC для учётных данных, используемых при подключении.

Модель интерактивного входа с личной Kubernetes identity предусмотрена архитектурой провайдеров, но пока не интегрирована полностью. Не следует считать, что каждое Web-подключение уже выполняется от индивидуальной Kubernetes identity.
