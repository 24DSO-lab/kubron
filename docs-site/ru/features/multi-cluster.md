# Управление несколькими кластерами

Добавляйте в Kubron несколько Kubernetes-кластеров и переключайтесь между ними без отдельных инструментов для каждого окружения. Один kubeconfig может содержать несколько контекстов: Kubron позволяет просмотреть их и выбрать нужный.

## Добавление и организация кластеров

В зависимости от версии можно импортировать kubeconfig из локального файла или вставить/загрузить его содержимое. Для кластера можно задать:

- отображаемое имя;
- цвет и иконку;
- тег окружения, например `dev`, `test`, `stage` или `prod`;
- namespace по умолчанию и необязательный опубликованный URL Argo CD.

## Выбор namespace

Выберите один, несколько или все namespace. Kubron не требует cluster-wide `list` только для работы с выбранным namespace. Если доступ к разным типам ресурсов или namespace отличается, частичные ошибки показываются явно, а не скрываются.

## Обновление данных и повторное использование подключений

Shared informers поддерживают актуальность списков ресурсов и дашборда без агрессивного polling. В Web multi-session mode у сессий свои активный кластер и интерактивные потоки, а безопасное повторное использование подключений кластера снижает лишнюю нагрузку.

## Владение кластером в Web

При включённом team mode с PostgreSQL каждый кластер принадлежит одной команде. Пользователь видит только кластеры команд, в которых состоит; его роль проверяется для выбранного кластера.

## Аутентификация зависит от версии

Desktop подключается с вашего компьютера и может использовать локальные kubeconfig exec plugins. Web подключается с сервера, поэтому отклоняет ссылки на локальные файлы и произвольные команды exec. В Web доступны статические учётные данные kubeconfig и текущий поддерживаемый OIDC password flow. Точный список приведён в разделе [Подключение к Kubernetes](/ru/features/cluster-auth).
