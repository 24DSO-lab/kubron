# Возможности Kubron


Kubron — Kubernetes Operations Workspace в двух версиях: desktop-приложение и самостоятельно разворачиваемая Web-версия. Основные рабочие сценарии общие. При подключении PostgreSQL Web дополнительно предоставляет совместный доступ, изоляцию команд и централизованное администрирование.

## Кратко о возможностях

| Возможность | Desktop | Web |
|---|---|---|
| Управление кластерами и ресурсами | Да | Да |
| Локальные пользователи и роли | Да | Да |
| Организация, команды и кластеры команд | — | Service mode с PostgreSQL |
| Helm, Argo CD и Flux CD | Да | Да |
| Дополнительный стек метрик Prometheus | Да, если вам можно создавать ClusterRole в кластере | Да, если учётная запись кластера может создавать ClusterRole |
| Несколько реплик сервера (HA) | — | Service mode с PostgreSQL |
| Терминалы Pod, debug-контейнеры, оболочка узла | Да, по праву | Да, по праву; администратор может их отключить |
| Вход через локальные `exec`-плагины | Да, после подтверждения команды | Нет: выполните плагин на своём компьютере и вставьте токен |
| Port-forward | Локальный порт | Локальный режим одного пользователя либо proxy mode с wildcard-доменом, который задаёт администратор |
| Журнал аудита | Файл в папке данных | PostgreSQL с настраиваемым сроком хранения и необязательной копией в стандартный вывод |
| Проверка обновлений и отчёты о проблемах | Да; проверку обновлений можно отключить | Проверку обновлений можно отключить; отчёты отправляются, только если администратор настроил почтовый сервер или приёмник |


## Кластеры и дашборд

- Подключение нескольких кластеров и контекстов; для каждого можно задать имя, иконку, цвет и тег окружения.
- Фильтрация по одному, нескольким или всем namespace; поддерживается ограниченный Kubernetes RBAC.
- Актуализация списков ресурсов через shared informers без агрессивного polling.
- Обзор здоровья кластера, узлов, workloads, capacity, хранилища, rollout и недавних изменений.
- Выявление проблемных Pod, перегруженных ресурсов, pending/lost PVC и TLS-сертификатов с истекающим сроком.
- Дополнительные графики использования ресурсов при установленном metrics stack.

## Ресурсы Kubernetes

- Просмотр workloads, сетевых, конфигурационных, storage-, RBAC- и policy-ресурсов.
- Автоматическое обнаружение CRD и отображение их `additionalPrinterColumns`.
- Подробности conditions, events, owners, containers, volumes и параметров планирования.
- Просмотр и редактирование YAML в Monaco с предварительным diff перед применением.
- Создание ресурсов из manifest, удаление объектов и поддерживаемые массовые действия.

## Операции

- Просмотр логов Pod и интерактивные терминалы при наличии разрешений.
- Масштабирование, перезапуск и rollback поддерживаемых workloads; операции с Job и CronJob.
- Cordon и drain узлов; node shell защищён отдельным привилегированным разрешением.
- Port-forward к Pod и Service с учётом версии и настроек сервера.
- Дополнительная установка Prometheus, kube-state-metrics и node-exporter в кластер.

## Диагностика инцидентов

- Расследование для Pod, Deployment, ReplicaSet, Service, PersistentVolumeClaim или Node: факты, гипотезы с уверенностью, рекомендации и недостающий контекст. Кластер не меняется, AI не используется.
- Проход по цепочке зависимостей, например Pod → PVC → StorageClass, до кандидата первопричины. Отсутствующий объект и объект, который не удалось прочитать, показываются по-разному.
- Доказательства из стека метрик, когда он доступен. Без него отчёт полный.
- Видно, какие ещё workloads зависят от того же источника, например от Node под давлением памяти, а связанные расследования объединяются в проблему.
- Отметка результата и статистика того, какие гипотезы и рекомендации помогали в вашем кластере. Ничего не отправляется автоматически.
- Расследование запускается действием **Расследовать** у ресурса или из раздела **Инциденты** в боковом меню.

## Жизненный цикл кластера

Группа **«Жизненный цикл кластера»** внизу бокового меню оценивает изменения до того, как они произошли. Обе проверки только читают кластер.

- [Готовность к обновлению](/ru/features/upgrade-readiness): устаревшие и удалённые API в живых объектах, совместимость kubelet и частых системных компонентов, путь обновления и отчёт, который говорит, что **не проверено**. Отчёты сохраняются историей, сравниваются с предыдущим и экспортируются в JSON или Markdown.
- [Baseline конфигурации](/ru/features/baseline): зафиксируйте конфигурацию выбранных ресурсов и затем проверяйте, что от неё отклонилось. Чувствительные значения хранятся только хешами, Secret не читаются. Kubron не применяет baseline и не исправляет дрейф.

## Helm и GitOps

- Каталог Helm-репозиториев и OCI registry, установка и обновление с dry-run и diff manifest.
- Просмотр values, manifest, notes, истории и diff ревизий; rollback и удаление релиза.
- Работа с Argo CD Applications, ApplicationSets и Projects: sync, refresh, rollback, diff и граф ресурсов.
- Работа с Kustomization и HelmRelease Flux CD, а также с источниками, уведомлениями и автоматизацией образов: состояние, ревизия, зависимости и управляемые ресурсы, reconcile, suspend, resume и удаление.

## Безопасность и совместная работа

- Встроенные роли `admin`, `operator` и `user` с проверкой детальных разрешений на backend.
- Локальные учётные записи, хеширование паролей, блокировка входа и автоматический выход.
- Журнал аудита привилегированных и административных действий.
- Web team mode разделяет пользователей и кластеры по организациям и командам; kubeconfig и Helm-секреты в PostgreSQL хранятся в зашифрованном виде.
- Нет телеметрии. Desktop хранит kubeconfig локально, и аккаунт в облачном сервисе Kubron не требуется. Раз в сутки Kubron обращается к GitHub, чтобы проверить обновления (это можно отключить, см. [Версия и обновления](/ru/features/updates)), а отчёт о проблеме отправляет, только когда вы нажмёте **Send** ([Сообщить о проблеме](/ru/features/bug-reports)).
