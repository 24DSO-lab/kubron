## Лицензия и sign-off

Код Kubron лицензирован под [Apache-2.0](https://github.com/24DSO-lab/kubron/blob/master/LICENSE). Отправляя изменение, вы подтверждаете, что вправе его вносить, и соглашаетесь лицензировать его под Apache-2.0. Отдельный CLA не требуется.

Pull request, открытый **из форка**, должен содержать строку DCO `Signed-off-by` в каждом коммите:

```bash
git commit -s -m "feat: ..."
```

Если забыли, `git commit --amend -s --no-edit` исправит последний коммит, а `git rebase --signoff <base>` — несколько. CI проверяет DCO только для pull request из форков. Pull request от коллабораторов репозитория подписи не требуют.

## Заголовки исходных файлов

Каждый файл `.go`, `.ts` и `.vue` должен начинаться с:

```
// Copyright 2026 The Kubron Authors
// SPDX-License-Identifier: Apache-2.0
```

Добавить автоматически: `python3 scripts/license-headers.py --fix`. Без заголовков CI падает.

## Текст интерфейса и локализация

В коде Kubron говорит по-английски, а фронтенд переводит на выбранный язык (English, Русский и 中文). Правила — в [docs/i18n.md](https://github.com/24DSO-lab/kubron/blob/master/docs/i18n.md). Чек-лист для каждого изменения:

1. **Не вписывайте текст для пользователя в код.** Добавьте ключ в `frontend/src/i18n/locales/en/<раздел>.json` и вызывайте `t('раздел.ключ')`.
2. **Добавьте ключ во все языки** с теми же плейсхолдерами. Источник — английский. Кириллица в коде вне `locales/` запрещена (в комментариях можно).
3. **Go возвращает только английский текст.** Новый `errors.New` или `fmt.Errorf` в `internal/` или `pkg/` требует шаблона в `backend.json` каждого языка. Бэкенд возвращает идентификаторы, а подписи подбирает фронтенд.
4. **Показывайте ошибки бэкенда через `errorText(e)`** и не принимайте решений по тексту ошибки.
5. **Форматируйте даты и числа через `i18n/format.ts`**, а не `toLocaleString('ru-RU')` и не вручную.
6. **Не вызывайте `t()` на верхнем уровне модуля**, только внутри функций, `computed` или рендера.
7. **Не переводите** имена объектов Kubernetes, поля YAML, статусы API и названия брендов.
8. **Тесты не должны зависеть от русского текста.** Unit-тесты работают с английским; end-to-end задают локаль и проверяют роли или `data-testid`.
9. **Никакого `v-html` с переводами.** Для разметки внутри текста используйте `<i18n-t>`.
10. Подумайте, как будет выглядеть русский и английский интерфейс (длина строк, множественные числа).

Pull request, который добавляет или меняет видимый текст, считается готовым, только если содержит переводы на все поддерживаемые языки.

## Зависимости

CI проверяет лицензии зависимостей (`go-licenses` для Go, `license-checker` для фронтенда). Разрешены Apache-2.0, MIT, BSD-2/3-Clause и ISC, а для Go ещё MPL-2.0. Зависимость с любой другой лицензией, включая GPL, AGPL и SSPL, нельзя добавлять без обсуждения.

## Перед pull request

```bash
gofmt -l .
go vet ./... && go test ./...
cd frontend && npm test && npm run i18n:check
```

Также соблюдайте [Code of Conduct](https://github.com/24DSO-lab/kubron/blob/master/CODE_OF_CONDUCT.md).

`npm run i18n:check` проверяет полноту ключей, плейсхолдеры, ссылки на несуществующие ключи, кириллицу в коде и необъявленные ошибки Go.

## Ветки

Повседневная работа идёт в `refactor` (или в feature-ветку) через pull request. В `dev` лежит то, что готово к выпуску, а в `master` — то, что уже выпущено. **Не открывайте pull request прямо в `master`.** См. [Выпуск релизов](/ru/development/releasing).

## Архитектурные решения

Напишите короткий ADR в [`docs/adr/`](https://github.com/24DSO-lab/kubron/blob/master/docs/adr/README.md) до кода или вместе с ним, когда изменение:

1. трудно или дорого откатить (формат хранения, схема, публичный RPC-контракт, формат хеша);
2. затрагивает несколько частей системы (ядро и обе оболочки, сервер и чарт, безопасность);
3. включает реальный выбор между вариантами, который кто-то может позже оспорить;
4. меняет или заменяет прежний ADR.

ADR — несколько строк: контекст, выбор, а также что отвергнуто и почему. Принятый ADR не редактируют; пишут новый, который его заменяет. Решения помельче записывают в описание pull request или в [`docs/decisions/`](https://github.com/24DSO-lab/kubron/blob/master/docs/decisions/README.md), когда их должен просмотреть человек.
