# Расширения (pkg/ext)

Kubron предоставляет публичное API на Go в `pkg/ext` для модулей, которые живут вне репозитория. Оно нужно потому, что код из `internal/` другой Go-модуль импортировать не может, поэтому всё, что внешний модуль должен реализовать или использовать, описано в `pkg/ext` и зависит только от стандартной библиотеки.

::: warning Нестабильное API
Контракты помечены как **нестабильные** до этапа SSO. `ext.APIVersion` (сейчас `1`) растёт при каждом несовместимом изменении, а `Registry.Install` отказывается подключать модуль, собранный под другую версию. Фиксируйте версию Kubron, под которую собираете.
:::

## Что есть сегодня

Весь Kubron, включая локальных пользователей, роли, журнал аудита, аварийный доступ администратора и работу над SSO/OIDC, — это Apache-2.0 в этом репозитории (ADR-0013). SSO пока не доступен в готовом виде: обе оболочки сообщают `SSO: false`, а вход в Kubron через SSO для организаций остаётся в планах. Контракты существуют, чтобы вход и хранилище можно было расширять или заменять без правок ядра.

Сервер пока не загружает внешние модули во время работы. Сегодня контракты реализованы внутри репозитория: хранилище PostgreSQL реализует интерфейсы хранения, а оболочки Wails и web реализуют `Platform`. `Registry` и пример модуля нужны, чтобы публичный контракт был проверен как собираемый и работающий отдельный модуль.

## Контракты

| Область | Типы | Назначение |
|---|---|---|
| Модули | `Module`, `Registry` | Модуль сообщает `Name()` и `APIVersion()` и регистрирует свои реализации в `Register(*Registry)`. `Registry.Install` проверяет версию. Реестр потокобезопасен |
| Вход | `Authenticator`, `PasswordAuthenticator`, `RedirectAuthenticator`, `Identity` | Способ входа в Kubron. `KindPassword` — форма логина и пароля внутри Kubron (локальные пользователи, LDAP). `KindRedirect` — перенаправление браузера к внешнему провайдеру (OIDC, SAML) с `BeginLogin` и `CompleteLogin` |
| Хранилище | `UserBackend`, `AuditBackend`, `TokenStore`, `UserRecord`, `SecuritySettings` | Постоянное хранение пользователей и настроек, записей аудита и токенов Argo CD API по кластерам |
| Оболочка | `Platform`, `Capabilities` | Что ядру нужно от оболочки: отправка событий, выбор файла, открытие ссылки, отчёт о возможностях |

Правила устройства, которые стоит учитывать:

- **Роли назначает ядро.** Аутентификатор возвращает подтверждённую `Identity` (subject, имя пользователя, отображаемое имя, email, группы, claims). Роль по ней определяют собственные правила Kubron, поэтому аутентификатор сам права не выдаёт.
- **Вход с перенаправлением не хранит состояние в модуле.** Всё, что нужно между двумя шагами, передаётся в `RedirectStart.State` (state, nonce, PKCE verifier). Ядро хранит его на сервере, в сессии или базе, поэтому схема работает с несколькими репликами.
- **Идентификаторы короткие и уникальные.** `Authenticator.ID()`, например `local` или `oidc`, попадает в URL и конфигурацию, а повторная регистрация завершается ошибкой.

## Минимальный модуль

`examples/ext-authenticator` в репозитории — полный протестированный модуль. Он регистрирует аутентификатор по паролю со статическим списком пользователей, только для иллюстрации:

```go
type Module struct{ users map[string]string }

func (m *Module) Name() string    { return "example-static" }
func (m *Module) APIVersion() int { return ext.APIVersion }

func (m *Module) Register(r *ext.Registry) error {
    return r.RegisterAuthenticator(&static{users: m.users})
}
```

Приложение подключает модули вызовом `registry.Install(example.New(users))`.

## Вместо расширения — вклад в проект

Если изменение относится к самому Kubron, например ещё один способ входа, сначала откройте issue и прочитайте [Участие в разработке](/ru/development/contributing). Поскольку `pkg/ext` — публичный контракт, любое его изменение сначала обсудите в issue.
